# 탭 스트립 UI 설계

## 의도

`--tgx-tabs` 실행에서 선택된 세션과 실행 상태를 한 줄로 보여 주되, 공급자 CLI가 소유한 VT 화면·입력·승인 흐름을 바꾸지 않는다. 이는 이후 TGX 시작 브랜딩을 같은 TGX 소유 영역에 추가할 수 있게 하는 안전한 화면 경계를 만든다.

## 목표와 제약

- 탭 모드에서만 상단 한 줄에 세션 번호, 선택 상태, 실행 상태, `Ctrl+T` 조작 힌트를 표시한다.
- 외부 터미널이 두 행 이상이면 그 한 행을 TGX가 예약하고 PTY/VT 모델에는 남은 행만 전달한다.
- 한 행 터미널에서는 스트립을 숨기고 기존 전체 높이를 보존한다.
- 탭 문자열은 ASCII 인쇄 문자와 고정 폭 절단만 사용하며, 자식 PTY 원시 바이트는 렌더러에 전달하지 않는다.
- 일반 단일 세션 경로, 공급자 인자, 입력, 붙여넣기, Ctrl+C, 승인 메뉴는 변경하지 않는다.

## 고려한 접근

1. 자식 화면의 첫 줄 위에 스트립을 덮는다. 구현은 짧지만 출력·메뉴의 첫 줄을 손상시킬 수 있어 제외한다.
2. 탭 모드의 PTY 높이를 한 줄 줄이고 상단 행을 TGX 프레임으로 렌더링한다. 선택한다. 화면 소유권과 좌표가 명확하다.
3. 별도 창/패널을 만든다. 향후 가능하지만 현재 PTY 래퍼 범위와 맞지 않는다.

## 설계

`SingleSessionLayout`은 선택적인 `tabBar` 기하 정보를 가진다. `computeTabbedSessionLayout`은 일반 레이아웃의 폭·sidecar 규칙을 재사용하고, 물리 행이 2 이상일 때에만 child rows를 하나 줄인다. `SidecarRenderer`는 tab bar가 있을 때 child와 sidecar의 ANSI 행 좌표를 하나 아래로 이동하고, 전체 첫 행을 탭 바 문자열로 안전하게 다시 그린다.

`createTabStripView`는 `ManagedSession` 스냅샷과 선택 ID로부터 고정 폭 ASCII 한 줄을 만들고, 화면 폭에 맞춰 절단·패딩한다. 탭 모드 CLI 렌더링만 이 상태를 네 번째 선택 인자로 전달한다. 기본 경로는 기존 세 인자 호출을 유지한다.

## 검증

- 레이아웃 단위 테스트: 넓은 sidecar/좁은 화면, 1행/2행 경계.
- 탭 스트립 단위 테스트: 선택·상태, 좁은 폭 절단, ASCII 안전성.
- 렌더러 단위 테스트: 상단 행과 child/dashboard의 행 오프셋, diff repaint.
- CLI 통합 테스트: 탭 모드 PTY가 줄어든 크기로 생성되고 탭 렌더 상태가 전달됨.

## 비목표

스크롤 분리, 마우스 조작, 탭 이름 변경, 시작 브랜딩 애니메이션은 이번 변경에 포함하지 않는다.
