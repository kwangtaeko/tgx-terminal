# TGX Terminal 설계 명세

작성일: 2026-10-17  
상태: 설계 승인됨 · 구현 계획 작성 전

## 1. 목표와 성공 기준

TGX Terminal은 기존 Codex CLI 또는 Claude Code를 자식 PTY에서 그대로 실행하는 Windows 우선 터미널 래퍼입니다. 사용자는 VS Code·Cursor의 통합 터미널 등 지원되는 호스트 터미널에서 `tgx codex` 또는 `tgx claude`를 실행합니다.

우선순위는 다음 순서로 고정합니다.

1. 입력, 승인, Ctrl+C, 리사이즈, 종료 및 터미널 복구의 정확성
2. 상태 데이터의 출처·단위·신선도 정확성
3. 자원 사용량과 렌더링 성능
4. 대시보드와 다중 세션 UX

P0의 성공은 실제 설치된 Codex와 Claude Code에서 한글 입력, 여러 줄 붙여넣기, 승인 메뉴, Ctrl+C, resize, alternate screen, 정상·비정상 종료 후 터미널 복구를 재현 가능하게 검증하는 것입니다. 어느 공급자·호스트 조합도 검증하지 못했으면 지원한다고 주장하지 않습니다.

## 2. 범위와 단계

| 단계 | 포함 범위 | 단계 종료 조건 |
| --- | --- | --- |
| P0 | 단일 PTY, VT 화면 모델, 입력·resize·종료 PoC | 핵심 상호작용의 실제 CLI 검증과 미검증 조합 기록 |
| P1 | 단일 세션 렌더러, 대시보드 UI, `unsupported` 상태 | 오른쪽 패널 오류나 숨김이 왼쪽 CLI를 방해하지 않음 |
| P2 | 실제 공급자 상태 어댑터, freshness·오류 격리 | 출처·버전·단위·갱신 방식이 검증된 값만 표시 |
| P3 | 탭, 독립 스크롤, 제한된 알림 | 선택 세션에만 입력이 전달되고 비활성 출력도 소비됨 |
| P4 | 좌우·상하 분할과 레이아웃 복원 | pane별 크기·포커스·수명주기 검증 |
| P5 | 성능·보안·로컬 패키징 검증 | 측정 결과, 알려진 제약, 지원표를 문서화 |

상태 대시보드 UI와 실제 상태 수집을 분리한다. P1은 정규화된 스키마와 명시적인 `unsupported` 상태만 제공한다. P2에서만 공식 인터페이스 또는 명시적으로 허용·검증된 로컬 이벤트를 실제로 수집한다.

## 3. 아키텍처와 경계

```text
사용자 입력
  -> 래퍼 명령 모드/포커스 라우터
  -> 선택 세션 PTY
  -> 원본 Codex CLI 또는 Claude Code

PTY 출력
  -> 세션별 VT 화면 모델과 유한 스크롤백
  -> 부모 터미널 렌더러

공식 상태 데이터 또는 검증된 로컬 이벤트
  -> 공급자 어댑터
  -> 정규화 상태 저장소
  -> 대시보드
```

- CLI 엔트리는 실행 파일과 인자 배열로 자식 프로세스를 시작한다. 셸 명령 문자열을 조립하지 않는다.
- 세션 매니저는 세션 ID, PTY, 프로세스 수명주기, 크기, 종료 코드, VT 모델, 스크롤 위치를 소유한다.
- 터미널 엔진은 자식 출력을 화면 모델에만 적용한다. 자식 출력 원문을 부모 stdout으로 직접 전달하지 않는다.
- 렌더러는 부모 터미널 화면을 소유하고 변경 영역만 다시 그린다. 세션 하나의 지우기 명령이 다른 pane이나 부모 화면을 침범하지 않아야 한다.
- 레이아웃과 대시보드는 PTY·VT 엔진에 의존하지 않고, 확정된 화면 상태와 세션 이벤트만 사용한다.
- 공급자 어댑터 실패는 세션 PTY, 입력, 렌더링을 멈추게 할 수 없다.

## 4. 입력·포커스·종료 계약

### 입력과 단축키

- 일반 입력, Tab, Ctrl+C, Esc, 붙여넣기는 기본적으로 선택된 자식 PTY에 전달한다.
- 래퍼 기능은 별도의 설정 가능한 명령 모드에서만 처리한다. 명령 모드의 기본 키와 탭 전환·스크롤·종료 키는 P0 PoC 결과를 토대로 정하고 문서화한다.
- 마우스 입력은 P0 필수 범위가 아니다. 도입 시 래퍼 조작 모드와 자식 CLI 마우스 모드의 우선순위를 명시한다.

### 종료와 프로세스 소유권

- Ctrl+C는 래퍼 종료가 아니라 선택된 자식에 전달한다.
- 래퍼가 명시적으로 종료되면 자신이 생성·소유한 프로세스 트리를 정상 종료 요청한 뒤, 정해진 대기 시간 이후 강제 종료한다. 정확한 Windows/ConPTY 메커니즘과 대기 시간은 P0에서 실험으로 확정한다.
- 자식의 정상 종료 코드와 비정상 종료 상태를 세션에 보존하고 사용자에게 구분해 표시한다.
- 어떤 종료 경로에서도 raw 모드, 커서 표시, 화면 속성은 부모 터미널에 복구되어야 한다.
- 래퍼 종료 후 자식 작업 지속은 MVP에서 보장하지 않는다.

## 5. VT·출력 보안 계약

- P0은 ANSI/VT 색상, 커서 이동, 줄 지우기, alternate screen, bracketed paste, 한글과 일반 wide character를 대상으로 한다.
- 결합 문자, emoji ZWJ, variation selector의 완전한 폭 호환성은 P0 합격 조건이 아니다. 실제 문제가 확인되면 fixture와 알려진 제약에 추가한다.
- 외부 렌더러는 필요한 화면 표현만 수행한다. OSC 52 클립보드, 창 조작 등 화면 외 효과를 유발하는 제어 시퀀스는 기본 차단한다.
- 알 수 없는 제어 시퀀스의 원문·대화 내용은 영구 로그로 저장하지 않는다. 필요 시 종류, 길이, 마스킹된 메타데이터만 크기 제한과 함께 기록한다.
- 세션별 스크롤백·출력 큐·진단 로그에는 상한을 두고, 테스트 fixture는 비식별화한다.

## 6. 상태 데이터 계약

각 항목은 `value`, `status`, `source`, `observedAt`, 선택적 `resetAt`, `reason`, 원본 window 및 단위를 가진다.

- 상태는 `available`, `unsupported`, `stale`, `error` 중 하나다.
- `remainingPercent`는 원본의 총량과 사용량이 명확하고 검증된 경우에만 계산한다.
- 세션 토큰, 컨텍스트 점유율, 구독 한도는 절대 서로 대체하거나 합산하지 않는다.
- 우선순위는 공식 인터페이스, 허용·검증한 로컬 이벤트/로그, `unsupported` 표시 순서다. 인증 파일, 비공개 인증 API, 자동 CLI 입력, 화면 텍스트 파싱은 기본 데이터 경로가 아니다.
- 각 소스는 `docs/data-sources.md`에 출처 URL, 확인일, 공급자·CLI 버전, 단위, TTL, 갱신 방식, 실패·백오프 정책을 기록한다.
- 마지막 정상값은 TTL 안에서만 `available`로 표시한다. TTL을 넘기면 `stale`로 전환하며 관찰 시각을 함께 표시한다. 수집 실패는 `error`이고 UI의 사유는 비밀을 제거한 정규화된 메시지만 사용한다.

## 7. 지원 플랫폼과 문서 증거

Windows 네이티브를 우선 지원한다. WSL2는 보조 검증 대상이고 Linux는 후속 검증 대상이다. `docs/compatibility.md`에는 각 검증 조합의 OS, 터미널 호스트, 셸, ConPTY 여부, Node·CLI 버전, 한글·paste·승인·Ctrl+C·resize·alternate screen·종료 복구 결과를 기록한다.

지원은 검증된 조합에만 선언한다. Windows Terminal, VS Code 통합 터미널, Cursor 통합 터미널, ConHost 및 사용 셸은 별도 행으로 관리한다.

`docs/validation.md`는 모든 명령, 환경, 기대 결과, 실제 결과, 미검증 사유를 기록한다. 실행하지 못한 검사는 통과로 표시하지 않는다. 호환성 실패 또는 범위 변경은 `docs/decisions/`의 결정 기록으로 남긴다.

## 8. 성능·알림·문서 정책

- P0 이후 고정 로컬 fixture로 직접 실행과 래퍼 실행을 같은 환경에서 최소 5회 비교한다. 자식 프로세스 포함 여부, warm-up, 시간 측정 방식, CPU/RSS 수집 방식을 함께 적는다.
- 초기 목표는 유휴 단일 세션의 추가 CPU 평균 1% 이하, 추가 RSS 100 MiB 이하, 입력→PTY 및 PTY 출력→flush의 내부 p95 각각 50ms 이하이다. 목표는 보장이 아니다.
- P3 알림은 탭 상태 표시와 터미널 벨로 제한한다. OS 알림은 명시적 동의와 별도 설계가 있을 때만 고려한다.
- README는 P5에서 인계 패키지 설명에서 설치·실행·단축키·제약·복구 방법을 설명하는 사용자 문서로 전환한다.

## 9. 제외 범위

- 공급자 CLI 포크 또는 대화 기능 재구현
- 사용자 전역 설정 변경, 승인·권한 제어 우회, 자동 CLI 입력
- 기본 원격 분석, 인증 비밀·대화 원문 저장 또는 전송
- 사용자 지시 없는 배포, npm 게시, 원격 저장소 생성
- MVP에서 래퍼 종료 후 작업 지속 보장
