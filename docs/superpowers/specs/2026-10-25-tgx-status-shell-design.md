# TGX 상태 셸 디자인

## 의도

TGX는 Codex·Claude Code의 본문 TUI를 다시 만들지 않는다. 입력, 승인, 중단의 호환성을 보존하면서 오른쪽 패널만 TGX 고유의 상태 셸로 소유한다. 사용자가 요청한 ccstatusline 계열의 정보 밀도는 확인 가능한 상태 데이터로만 표현한다.

## 목표

- 30열 ASCII 패널에서 즉시 TGX 소유 화면임을 식별한다.
- 공급자, CLI 버전, 사용량 정보 상태, 공식 문서 출처를 섹션으로 구분한다.
- 사용량 값이 수집되지 않은 경우에도 0%, 토큰, 비용, 모델명, 남은 시간처럼 추정값을 만들지 않는다.
- 모든 행은 기존과 같이 고정 폭 printable ASCII로 제한해 Windows 콘솔의 wide-character 폭 차이에 의존하지 않는다.

## 비목표

- 제공자 본문이나 로고를 모사하지 않는다.
- provider API를 호출하거나 인증 정보·대화 내용을 수집하지 않는다.
- 실제 세션 상태, Git 정보, 모델명, 토큰 사용량처럼 아직 계약에 없는 데이터를 표시하지 않는다.

## 검토한 방식

1. 기존 `TGX STATUS` 라벨만 꾸민다: 변화가 작지만 TGX만의 정보 구조가 생기지 않는다.
2. **선택: ASCII 상태 셸**: `TGX / TERMINAL`, `SESSION`, `USAGE SIGNAL`, `PRIVACY` 섹션과 구분선을 사용한다. 제공자와 무관하고 현재 데이터 계약 안에서 정확하다.
3. 제공자별 복제 UI: 입력 호환성은 유지하더라도 사용자가 원하는 TGX 고유 UI와 반대이며 유지비가 높다.

사용자는 반복적으로 자율 진행을 요청했으므로 2번을 기본 선택으로 구현한다.

## 표시 계약

- 헤더: `TGX / TERMINAL`
- 세션 섹션: `PROVIDER`, `CLI`
- 사용량 섹션: `STATE`, `SOURCE`
- 개인정보 섹션: `LOCAL STATE ONLY`
- unknown/unsupported/error/stale는 실제 `usage.status`만 표시한다.

## 검증

- 지원되지 않는 Codex 상태가 정확한 헤더·섹션·provider·버전·상태·출처를 갖는다.
- 민감한 내부 `reason` 및 추정 사용량은 출력되지 않는다.
- 좁은 폭·높이에서도 기존처럼 잘리고 모든 행의 폭이 고정된다.
