# 다중 세션 코어 설계

작성일: 2026-10-24
상태: 구현 범위 확정

## 의도

P3의 탭과 독립 스크롤은 각 공급자 CLI를 별도 PTY와 VT 화면 모델로 유지해야 한다. 동시에 P0의 핵심 계약인 일반 입력, Tab, Ctrl+C, Esc, 붙여넣기를 선택된 자식 CLI에 그대로 전달하는 동작은 보존해야 한다.

## 목표

- 세션마다 PTY, VT 화면 모델, 출력 구독, 종료 상태를 독립적으로 소유한다.
- 선택된 세션에만 입력을 전달하고, 실행 중인 모든 세션에 resize를 전달한다.
- 한 세션의 출력, 종료, 렌더 실패가 다른 세션의 화면이나 입력 경로를 오염시키지 않는다.
- 보존된 종료 탭을 포함한 세션 수와 각 화면의 기존 scrollback 제한을 함께 사용해 메모리 증가를 제한한다.

## 비목표

- 이번 증분에서 부모 터미널의 키를 가로채는 탭 생성·전환 단축키를 추가하지 않는다.
- 기존 `runCli` 단일 세션 경로, 사이드바, 공급자 사용량 수집을 바꾸지 않는다.
- 자식 CLI의 출력 텍스트를 파싱해 상태나 사용량을 만들지 않는다.

## 접근 방식

1. 부모 입력을 가로채는 기본 단축키를 즉시 추가한다. 구현은 빠르지만 Ctrl+C, 승인 메뉴, 붙여넣기와의 충돌을 피할 수 없다.
2. 명시적 prefix 명령 모드를 먼저 도입하고 탭 UI를 붙인다. 충돌은 줄지만 prefix 형식과 도움말·오류 UX를 별도로 결정해야 한다.
3. **선택: 키를 가로채지 않는 다중 세션 코어를 먼저 도입한다.** `MultiSessionManager`가 세션별 PTY와 `ScreenOutputModel`을 격리하고, 선택 API를 통해서만 입력을 전달한다. 이후 명시적 opt-in 명령 모드가 결정되면 이 API를 소비한다.

선택 이유: 현재 P0는 모든 키를 선택된 PTY로 그대로 전달한다고 검증한다. 탭 UI의 키 바인딩을 먼저 추가하면 가장 중요한 호환성 계약을 추측으로 바꾸게 된다.

## 계약

- `MultiSessionManager`는 생성 시 상한 `maximumSessions`를 받아 이를 넘는 생성 요청을 거부한다.
- 세션 ID는 관리자만 만든다. 외부 입력으로 ID를 조립하지 않는다.
- 각 세션의 출력은 자기 `ScreenOutputModel.write` 직렬 체인에만 기록한다.
- 선택되지 않은 세션은 출력과 종료 상태를 계속 갱신하지만 입력을 받지 않는다.
- resize는 실행 중인 모든 세션의 PTY와 화면 모델에 같은 검증된 크기로 적용한다. 종료된 탭의 마지막 화면 크기는 바꾸지 않는다.
- 자연 종료한 탭은 마지막 화면과 exit 상태를 보존하며, `maximumSessions` 상한을 계속 점유한다. 새 탭을 만들려면 호출자가 종료 탭을 명시적으로 `close`해야 한다.
- 화면 모델 쓰기가 실패하면 해당 세션만 `error` 상태로 전환하고 이후 출력을 버린다. PTY는 자동 종료하지 않으며 다른 세션은 계속 동작한다.
- 각 세션의 보류 출력은 설정된 UTF-8 바이트 상한과 512개 chunk 상한을 넘기지 않는다. 초과분은 해당 세션만 `error`로 전환해 버리며, 다른 세션의 출력 경로는 유지한다.
- 자연 종료와 명시적 close는 이미 수신해 대기 중인 화면 쓰기를 drain한 뒤에만 화면을 dispose한다. 화면이나 구독 생성이 실패하면 획득한 PTY를 즉시 close해 누수를 막는다.
- `close`와 `closeAll`은 구독을 해제하고 화면 모델을 dispose하며, 하나의 close 실패가 나머지 정리를 멈추게 하지 않는다.

## 검증

- 두 개의 fake session으로 선택된 세션만 입력을 받는지 검증한다.
- 서로 다른 출력과 화면 snapshot이 섞이지 않는지 검증한다.
- resize, 종료 직전 출력 drain, 종료 탭 보존, 화면 쓰기 실패·출력 상한 격리, 생성 rollback, 전체 종료를 포함한 fixture 기반 단위 테스트를 추가한다.
- 전체 Vitest, strict typecheck, build와 diff 검사를 실행한다.

## 후속 결정

사용자가 명시적으로 활성화하는 wrapper 명령 모드의 진입 키·도움말·종료 동작은 별도 설계에서 결정한다. 이 코어는 그 결정을 강제하지 않는다.
