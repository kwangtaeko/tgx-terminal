# P0 수동 호환성 검증 절차

## 목적과 기록 원칙

이 절차는 실제 공급자 CLI의 대화형 경로만 확인합니다. 별도 빈 작업 폴더에서 실행하고, 프롬프트·대화 내용·인증 정보·토큰·파일 전문은 기록하지 않습니다. 각 항목은 `pass`, `fail`, `not verified` 중 하나로만 [compatibility.md](./compatibility.md)에 기록합니다.

## 사전 조건

```powershell
pnpm build
node dist/cli.js codex
```

Claude Code도 같은 방식으로 `node dist/cli.js claude`를 실행합니다. 공급자 CLI가 인증이나 업데이트를 요구하면 자동화하거나 우회하지 말고, 해당 항목을 `not verified`와 이유로 기록합니다.

## 공급자별 확인 항목

각 공급자에서 아래 순서대로 수행합니다.

| 순서 | 확인 | 통과 기준 | 실패 증상 |
| --- | --- | --- | --- |
| 1 | 시작 | TGX가 alternate screen으로 전환되고 공급자 UI가 표시된다 | 빈 화면, 즉시 종료, 부모 셸 훼손 |
| 2 | 한글 입력 | 짧은 비밀 없는 한글 문장이 깨지지 않고 공급자에 전달된다 | 분리된 자모, 물음표, 누락 |
| 3 | Backspace | 짧은 한글 문장 끝에서 Backspace 한 번마다 마지막 글자 하나만 삭제된다 | 단어 단위 삭제, 조합 중 글자 누락, 화면과 실제 입력 불일치 |
| 4 | 여러 줄 붙여넣기 | 두 줄의 비밀 없는 텍스트가 순서·줄바꿈을 유지한다 | 줄 합침, 중복 전송, 일부 누락 |
| 5 | 승인 메뉴 | 공급자가 자체 승인 메뉴를 표시하는 경우 메뉴 이동·취소가 가능하고 실제 작업은 실행하지 않는다 | 메뉴가 보이지 않거나 입력이 부모에 전달됨 |
| 6 | Ctrl+C | 장시간 응답 또는 안전한 대기 상태를 중단하고 세션이 멈추거나 공급자 정책대로 취소된다 | 부모 TGX가 종료되거나 입력이 멈춤 |
| 7 | resize | 창의 열·행을 크게 바꾸고 공급자 UI가 다시 그려진다 | 화면 깨짐, 충돌, 고정 폭 |
| 8 | alternate screen | 전체 화면 UI가 표시되는 동안 부모 셸의 기존 내용이 오염되지 않는다 | 자식 ANSI가 부모 셸에 남음 |
| 9 | 정상 종료 | 공급자 종료 뒤 커서가 보이고, raw 입력·alternate screen이 복구되어 부모 셸 명령을 입력할 수 있다 | 숨은 커서, 입력 불가, 깨진 화면 |
| 10 | 강제 중단 | 별도 실행에서 Ctrl+C 또는 안전한 종료 방법 뒤에도 9번의 복구 기준을 만족한다 | 고아 프로세스, 복구 실패 |

## 기록 예시

대화 내용 대신 다음 수준만 기록합니다.

```text
2026-10-17 | Codex CLI 0.163.0 | 여러 줄 붙여넣기 | pass | VS Code 통합 터미널
2026-10-17 | Claude Code 2.1.302 | 승인 메뉴 | not verified | 승인 메뉴가 재현되지 않음
```

P0 전체 통과는 두 공급자에서 1~10번을 모두 확인한 경우에만 선언합니다. 하나라도 실패하면 공급자·호스트·항목·재현 조건만 남기고, 대화 원문은 남기지 않습니다.
